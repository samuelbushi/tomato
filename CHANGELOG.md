# Changelog

## Unreleased — portable Node/PostgreSQL product

- Move the shared monitoring product to TypeScript/Node.js 24, PostgreSQL and Better Auth, with real HTTP(S), heartbeat, DNS/DoH, WebSocket, TCP and TLS execution, durable evidence, incidents/recovery and configured alerts.
- Keep the square grey/blue old-Windows native interface, workspace roles, public status, scoped REST/MCP management and revocable key delegation. Core native forms support operation without optional JavaScript.
- Provide complete self-hosted monitoring without a mandatory provider account, license activation or purchased Tomato credits. Hosted mode uses the same engine and exact eligible-primary credit ledger; retail payments/prices are not fabricated by that meter.
- Keep hosted operator provisioning unfunded when `testingCredits` is omitted or explicitly zero. Validate explicitly supplied amounts before creating an identity/workspace; positive operator testing grants are audit-tagged and idempotent, not customer payments or implied welcome credits.
- Add secure owner bootstrap, explicit HTTPS/prober/database isolation, tracked migrations, identity-preserving restart/upgrade and authenticated full encrypted backup/restore for the supplied Docker Compose package.
- Remove the requirement for an advance per-user contact CSV: append stable product identities, preserve existing IDs/roles/API-key lineage and support restricted original-password claims with real, same-browser SMTP contact verification. Keep mapped full legacy login bounded while unmapped restricted enrollment remains available after that bridge expires; original shorter passwords are unchanged, not reset.
- Preserve unmapped invitation tokens and exact target/workspace/role through verified new-user enrollment without letting invitation possession claim an existing legacy principal. Email collisions and OAuth linking cannot merge/hijack identities.
- Add explicit operator staging workload freeze without pausing/revising monitors, and optional durable shared SMTP day/hour admission covering auth and alerts. Keep public recovery receipts neutral and truthful for existing and unknown contacts; authenticated enrollment/invitations observe actual callback failure. Send only one validated address per envelope.
- Preserve failed-email invitation identities/passwords and provide a native resend form; verify the actual recipient before membership. Keep request-local SMTP failure honest and isolate durable mail admission from a saturated main transaction pool, including secret-file PostgreSQL passwords.
- Add optional transport-only HMAC gateway ingress with body/header/origin/timestamp binding, durable PostgreSQL nonce replay fencing across restart, duplicate-critical-header rejection and unchanged native authorization. Keep ordinary transport credential lifetime separate from finite migration control; an attestation is not a feature gate or product permission.
- Exercise native Node/PostgreSQL workflows in controlled endpoints and normal Chrome desktop/390px views, and the actual Linux ARM64/PostgreSQL 18 package through first-run, restart, full restore, restored stored-secret checks and HMAC-validated webhook delivery.
- Prepare Apache-2.0 source licensing, retained third-party notices and contributor/security guidance. Dependencies and upstream runtime/database/proxy components retain their own licenses.

The existing Cloudflare-hosted service remains on its previous release. These source changes do not perform a live migration, public-host cutover, commercial signup/payment launch or new provider approval. Authorized final source export/quiescence, host/domain activation, approved mail/OAuth and merchant/pricing/legal decisions remain separate commercial prerequisites; a static legacy-contact map is no longer one of them.
